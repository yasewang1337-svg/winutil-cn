# MCP 版本变更

## 0.4.3

- 将 npm 包作者与中文维护署名统一为 `yesewang1337`，并同步包内接入示例至本版本。
- 软件包名称、源码仓库地址和可信发布配置保持不变；运行代码、依赖与支持的操作范围无变化。

## 0.4.2

- 更新随包分发的 README，移除已过时的 npm 认证与发布状态说明；所有接入示例固定到本版本，避免 npm 与 GitHub 文档给出相互矛盾的安装指引。
- 补齐 npm 包的源码子目录、中文文档站和问题反馈入口。
- Windows 备用接入与恢复说明改用持久本地 npm 安装目录，不再依赖维护者的 `W:` 源码目录；仍调用现有 worker，未新增修改或恢复命令。
- 实际 tarball 验证同时检查接入版本、包元数据和恢复脚本完整性。运行代码、依赖版本和支持的操作范围不变。

## 0.4.1

2026-10-11 已[发布 GitHub 安装包](https://github.com/yasewang1337-svg/winutil-cn/releases/tag/mcp-v0.4.1)，附实际 Windows 验证摘要；2026-10-12 已通过可信发布补发至 [npm 0.4.1](https://www.npmjs.com/package/winutil-cn-mcp/v/0.4.1)，SHA512 与原 GitHub 安装包一致。

- 修复从 PowerShell 7 经 Node/.NET 启动 Windows PowerShell 5.1 时，继承的模块搜索路径导致备份或恢复加载错误模块的问题。worker 仅调整自身进程的模块目录，同时覆盖修改和直接恢复入口。
- 新增三台 GitHub 托管一次性 Windows 测试机的实际修改与恢复验证，覆盖注册表类型、服务启动配置、DNS、包源、软件安装，以及真实写入后取消再恢复；详见 [测试范围](test/integration/README.md)。
- 发布包构建以普通回归和实际修改测试为前置条件。npm 上传由维护者手动明确启用；可信发布限定本仓库工作流，支持验证来源与哈希后补发原包，不重建不同内容覆盖同版本。

## 0.4.0

2026-10-11 已[发布 GitHub 安装包](https://github.com/yasewang1337-svg/winutil-cn/releases/tag/mcp-v0.4.0)；该版本未上传 npm，请使用后续 0.4.1，接入方式见 [当前指南](https://github.com/yasewang1337-svg/winutil-cn/blob/main/mcp/README.md)。

- 默认只读；修改工具须显式启用，全部改为先预览、相同参数与一次性计划确认。
- 修复错误被成功文本覆盖的问题，提供逐项结果、原始输出与 MCP 错误标记；增加互斥、过期计划和取消处理。
- 取消或超时后保留备份编号和已确认范围；客户端可通过 `get_status` 回看当前连接最近一次执行结果，未知范围会明确标记。
- 优化执行改为受控声明式注册表/服务操作，不再运行目录里的任意脚本；明确标记尚不支持的复杂项目。
- DNS 改为显式选择网卡并复核身份，系统配置修改前保存受控备份；换源保留原配置并修复 Windows npm/yarn 入口。
- 查询支持分页、软件 key、组合默认推荐与用途，并增加版本、数据来源及执行状态查询。
- 源码优先读取当前配置，发布包使用有来源记录的快照；移除运行时远程配置回退，修复普通 npm pack 漏数据。
- 更新依赖与 Node 支持范围，加入 Windows/Linux MCP 专项回归、真实离线包验证和先测试后发布流程。

兼容性变化：旧客户端若曾直接调用修改工具，需要显式添加 `--allow-write` 并采用预览/确认流程；旧的 `confirm:true` 单独调用不再执行。DNS 不再默认修改全部已连接网卡。复杂脚本优化转由桌面版处理。查询新增分页，完整遍历请使用 `offset` 与 `hasMore`。

2026-07-09 发布，提供八个查询/修改工具及包内目录快照。该版本没有强制只读和统一确认，系统修改存在错误反馈、执行依赖及下载校验缺口，建议升级。
