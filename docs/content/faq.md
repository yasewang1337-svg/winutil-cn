## 运行与更新

### 我应该下载哪个文件？

普通使用下载[最新发布页](https://github.com/yasewang1337-svg/winutil-cn/releases/latest)中的 **WinUtil-CN.exe**，核对发布页的 SHA256 后双击打开。EXE 内嵌固定版本脚本，使用 Windows 自带的 PowerShell 5.1，无需另装 PowerShell 7。步骤见[快速上手](/userguide/getting-started/)。

`winutil-cn.ps1` 是面向熟悉 PowerShell 的用户的脚本入口。GitHub 自动生成的 Source code 压缩包是源码，不是编译好的桌面软件。

### 支持 Windows 10 吗？

桌面工具的目标运行环境是 **Windows 11**。镜像制作支持 Windows 10 / 11 x64 安装介质，但不代表工具已支持在 Windows 10 上运行。Windows Server、LTSC 和 ARM64 不作为本工具完整桌面功能已验收的运行环境。

### 为什么打开时就需要管理员权限？

当前桌面版启动时会申请管理员权限，用于软件管理及受支持的系统操作。首页导航、挑选组合和导入图形界面清单本身不会自动安装软件或执行设置；仍需查看并确认操作。组织管理的电脑应先确认组织策略允许使用。

### 关闭或删除工具，会恢复之前的改动吗？

不会。工具无需常驻，但已安装的软件和已执行的系统更改会保留。本地日志、设置历史和镜像工作目录也可能保留。删除下载的 EXE 不会卸载第三方软件或撤销设置；需要时按对应功能的恢复说明处理。

### 它会自动更新吗？

桌面 EXE 固定包含下载时的脚本，不会每次打开都下载最新代码。需要新版时，从本项目发布页重新下载，关闭旧窗口后替换文件。MCP 是独立 npm 包，更新桌面版不会自动更新 MCP，反之亦然。

### 哪些操作需要联网？

下载工具、准备包管理器、安装和更新第三方软件需要联网。EXE 打开时不下载主脚本；部分设置可以本地执行，但访问在线资源的具体功能仍需要网络。离线打开不等于所有功能均可离线使用。

## 软件管理

### 软件从哪里下载？能保证每个安装包都没有广告吗？

WinUtil CN 调用 WinGet 或已安装的 Chocolatey，按软件包 ID 交给相应来源下载安装。第三方安装包、许可和应用自身的广告行为由发布者决定，工具不保证所有软件都无推广或适合所有用途。确认窗口显示本次软件包 ID 与使用的包管理器。

### 能安装、更新和卸载吗？

可以。在软件管理页选择项目，再使用 **安装 / 升级…** 或 **卸载…**，核对操作范围。**查看全部升级操作**可能包含本工具目录外的软件，目前不提供逐软件待更新列表。完整边界见[应用管理](/userguide/application/)。

### “检测已安装”没有显示某个软件，是不是没装？

不能这样判断。检测只匹配当前包管理器可识别、且本工具目录中存在的项目。软件名称相似也不一定是同一软件包 ID。切换来源、检测失败或开始软件操作后，应重新检测；已安装也不表示一定有可用更新。

### 部分安装失败怎么办？

先查看 **软件操作结果** 中的中文原因、退出码和日志。支持的逐项操作可使用 **仅重试失败项**，无需重做成功项。日志在 `%LOCALAPPDATA%\WinUtil-CN\Logs\Packages`；窗口中的 **打开日志文件夹**可直接进入。不要只凭“未显示窗口”判断安装成功。

## 设置与恢复

### 能完整撤销所有优化吗？

不能。**恢复所选设置**使用本版本保存的历史记录，恢复受支持的注册表值和服务启动配置。没有记录的项目会跳过；服务运行状态、已删除应用、清理的文件和脚本的其他改动不支持完整恢复。细节见[设置与恢复](/userguide/tweaks/)。

### 应该一开始就全选优化吗？

应按实际需求选择，先阅读说明及执行计划。基础方案也不保证适用于所有电脑，不以增加勾选数量衡量效果。需要保留的数据应另行备份；工具的设置历史不代替个人文件备份或系统还原。

### “延迟更新”是不是只接收安全补丁？

不是。它尝试调整功能和质量更新的延迟天数，质量更新也包含安全修复。从禁用状态返回时，应先使用 **恢复更新配置** 并检查实际状态；直接切换到延迟模式不能保证恢复已停用的服务或任务。恢复更新配置也不会还原修改前所有个人或组织策略。详见[Windows 更新](/userguide/updates/)。

### 能保证性能提升或提高游戏帧率吗？

不能。功能效果取决于硬件、Windows 版本和现有配置。先明确具体问题，保留可比较的测试条件；不建议为了笼统的“优化”批量关闭服务或安全功能。

## MCP 与问题反馈

### MCP 会直接操作已打开的软件窗口吗？

不会。MCP 是独立的 Node.js 包，通过标准协议提供目录查询和受控执行。默认只注册查询工具；写操作需要显式启用并核对计划。安装与恢复说明见[MCP 接入](/mcp/)。

### 遇到安全软件告警、执行策略或“拒绝访问”怎么办？

记录版本、威胁名称或完整错误、文件 SHA256 及发生步骤，按[安全告警说明](https://github.com/yasewang1337-svg/winutil-cn/blob/main/docs/SECURITY.md)核对与提交复核。不能仅凭开源断定是误报，也不应通过关闭防护、扩大文件权限或降低执行策略来消除告警。受组织策略限制时请联系管理员。

### 反馈问题需要提供什么？

在[本项目 Issues](https://github.com/yasewang1337-svg/winutil-cn/issues)提供工具版本、Windows 版本、启动方式、复现步骤和相关日志片段。发布前删去个人路径、账户信息等无关内容。当前边界见[已知问题](/knownissues/)，贡献方式见[贡献指南](/contributing/)。
